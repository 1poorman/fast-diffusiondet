# B1：仅骨干使用FP16 autocast

协议固定于2026-10-14，结果产生前记录。L1显示骨干约占H4/P300的41% stream区间，
减框则保留大部分逐级调度/同步。本轮独立改变推理精度，不改框数、深度、权重或训练目标。

## 实现边界

- `EVAL_BACKBONE_PRECISION=fp32`默认保留原路径；`fp16`仅在推理时对backbone/FPN开启CUDA autocast。
- backbone输出转回FP32后才进入ROIAlign、attention、分类/回归、采样和后处理。
  图像预处理、噪声和框坐标保持FP32。autocast按算子选择类型，并非所有骨干算子均强制半精度。
- 不转换存储参数或buffer，不修改checkpoint键，旧权重严格加载；训练忽略这个推理选项。
- FP16选项要求CUDA、FP32图像输入及无外层CUDA autocast，避免无意中将检测头也降精度。
- 特征还原和每次调用的autocast开销都计入延迟，不用预先缓存特征或改动输入尺寸获得加速。

## 固定矩阵与数值检查

使用T1 seed10/11/12三份600步uniform H4末步权重；P300、NFE1、原focal、no_weights，
共享300框噪声、固定pre-NMS top-k300。FP32/骨干FP16两臂，推理seed0/1/2，
18次完整750图SDD开发验证，先平均推理seed再跨checkpoint配对。权重不重新训练。
奇偶训练seed+推理seed反转两臂顺序。只使用GPU1，4个CPU线程，TF32/cuDNN benchmark关闭，
cuDNN deterministic关闭；全模型AMP、EMA、QFL、减框均不叠加。

每份权重的前两张图审计stem输出、原始FPN输出、head输入/输出和最终框/分数dtype。
FP16臂必须实际观察到FP16卷积/FPN计算，而head边界与最终输出必须为FP32。
报告同层特征最大绝对误差和相对L2误差，但不将其代替完整AP评测。
检查所有最终预测有限、权重状态起止digest一致；FP32九次所有总体/逐类AP必须复现T1。
冒烟仅seed10、推理seed0、32图；不根据冒烟AP挑选参数或作性能结论。

## 延迟测量与预设门槛

完整评测内仍记录20图预热+随后200图的CUDA同步模型调用p50/p95与峰值allocated显存。
L1观察到跨遍计时漂移，因此另外对相同三份权重、推理seed0/1/2做逐图交错计时：
每张图两臂使用同一噪声seed，按图序号+训练seed+推理seed奇偶执行AB或BA，
每臂前20图预热、随后同200图计时，共9组配对，作为速度门槛的主要证据。
生成完整噪声池、骨干autocast/特征还原和完整模型调用都在计时内；不含读取/CPU resize、
设置随机种子、evaluator和数值审计。计时阶段没有dtype hooks或profiler。

只有全部满足才列为开发部署候选：

1. 平均ΔAP≥−0.3、平均ΔAP75≥−0.3，且每份checkpoint的平均ΔAP≥−0.5。
2. 最差类别平均ΔAP≥−1.0；全部预测与特征审计有限，FP32控制复现通过。
3. 交错计时的p50平均降低至少15%，每份checkpoint至少降低10%；平均p95增幅≤5%。

不以单个有利seed选型，不更改以上门槛。通过仍只是反复使用的SDD开发集候选，
后续需要未用于选型的数据确认；精度模式收益单独列示，不归因于新结构或训练增强。
FP16若出现非有限值则停止并记录，不自动换BF16或改变条件后宣称通过本轮。
所有新日志/预测保留于新的`runs/v3/`目录，旧权重只读。
